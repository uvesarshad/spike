## Summary (the short version)

- The Software runs **locally on your machine**. It drives a real Chrome browser to test your web app and produce a verdict.
- We do **not** operate a server that receives your data, and we collect **no analytics or telemetry**. There is no account and no first‑party data collection.
- To do its job, the Software sends the page content it observes to the **AI model you choose**. Where that goes depends entirely on your configuration (see "Where your data goes" below). The cheapest tiers — on‑device Gemini Nano and local Ollama — send **nothing off your machine**.
- Your **API keys and secrets are stored encrypted on your device** and are never sent to us. Keys are transmitted only to the corresponding model provider to authenticate your own requests.

## What the Software processes

When you run a QA task, the Software captures and processes, **on your machine**:

- **The task description and target URL** you provide.
- **Page structure** — a compact accessibility (a11y) tree of the page under test (element roles, names, and text).
- **Screenshots** of the page — used only for visual checks, and only sent to model providers that accept images (see below).
- **Console messages and network request/response metadata** generated by the page during the test, captured for diagnostics.
- **Run artifacts** — a `report.json`, screenshots, and optional replay clips, written to a local `artifacts/` directory. The extension also keeps a short **run history** in your browser's local storage (`chrome.storage.local`).

The Software is intended for testing applications **you own or are authorized to test**. By default it only clicks/types on `localhost`/`127.0.0.1`; mutating actions on other hosts require your explicit opt‑in. You are responsible for the content of the pages you direct it to test.

## Where your data goes (the model ladder)

The Software uses a configurable "ladder" of AI models. The data that leaves your machine — if any — depends on which rung handles a given step:

| Rung | Model | Data leaves your machine? |
|---|---|---|
| 0 | **Gemini Nano** (on‑device, in Chrome) | **No.** Runs entirely locally; no network calls. |
| 1 | **Claude Code CLI / Codex CLI** (your own logged‑in CLI) | Yes — page text/screenshots sent to **Anthropic** or **OpenAI**, authenticated with your existing CLI session. |
| 2 | **BYOK** — Gemini API, Anthropic, OpenAI, OpenRouter, **GLM / z.ai** | Yes — sent to **the provider you configured**, authenticated with your key. |
| 3 | **Ollama** (local) | **No.** Runs on your own machine/network. |

Notes:

- **You control the rung.** Pin an on‑device/local model (Gemini Nano or Ollama) to keep all data on your machine. Pick a cloud provider and the relevant page content is transmitted to that provider to generate the next action or verdict.
- **Google's free Gemini CLI tier was discontinued on 2026‑06‑18** and is no longer a data destination. If you have an older configuration that still points at it, update it — see the project README for current rung options.
- **Screenshots** are only sent to providers that accept image input. Text‑only models — including **GLM‑5.2 (z.ai)** — receive only the a11y‑tree text and your task description, **never screenshots**.
- When a step is uncertain or a provider is unavailable, the Software may **escalate to the next rung**, sending that step's data to the next configured provider. Every such hop is recorded locally in the run's `model_trace`.

### Third‑party model providers

When you choose a cloud provider, your use of it is governed by **that provider's** privacy policy and terms, not ours. Review them before sending sensitive data:

- **Google (Gemini API):** https://ai.google.dev/gemini-api/terms and https://policies.google.com/privacy
- **Anthropic (Claude API / Claude Code CLI):** https://www.anthropic.com/legal/privacy
- **OpenAI (GPT API / Codex CLI):** https://openai.com/policies/privacy-policy
- **OpenRouter:** https://openrouter.ai/privacy
- **z.ai (GLM‑5.2):** https://z.ai/ — see the z.ai terms and privacy policy and the API docs at https://docs.z.ai/
- **Ollama:** runs locally; no third‑party transmission.

Provider data‑retention and training‑on‑inputs practices vary and may change. If you require that your inputs are not retained or used for training, configure a provider/plan that contractually guarantees this, or use the on‑device (Nano) or local (Ollama) rungs.

## API keys and secrets

- **API keys** you provide are stored in an **encrypted, on‑device vault** (AES‑256‑GCM). The vault's encryption key itself is protected differently by platform: on **Windows**, it's wrapped by the OS DPAPI, bound to your user account. On **macOS/Linux**, it is currently a **local key file with `0600` permissions** (owner‑read/write only) rather than OS‑keychain‑backed — a deliberate v1 tradeoff, disclosed here rather than hidden. OS‑keychain backends (macOS Keychain, Linux `libsecret`) are **planned** to bring those platforms to keychain‑backed parity with Windows' DPAPI. Keys are decrypted only in memory at request time and sent **only** to the matching provider's API endpoint to authenticate your requests. **We never receive your keys.**
- **Secrets** you reference in a task as `{{secret:NAME}}` (e.g. login passwords) are also stored in the encrypted vault and are **never sent to any AI model**. They are substituted into the page only at the moment of typing, locally.
- If you instead type a credential **directly into the task text** ("log in with me@example.com / hunter2"), it **is** sent to the model — it has to be, for the model to use it. Credential‑shaped text is stripped out of what we then write to disk (report, recorded test, run history) and out of the fix prompt, and a value typed into a password‑style field is stored as `•••` — but **screenshots and replay clips are not redacted**, so the field's contents can still be visible in an image. Use the vault (`{{secret:NAME}}`, or the panel's "Test login (optional)" card) for anything real.

## What we do *not* do

- We do **not** run a backend that collects, stores, or processes your data.
- We do **not** include analytics, tracking, advertising, or telemetry.
- We do **not** sell or share your data (we don't have it).

## Data retention and deletion

- Run artifacts and logs live in local directories you control (`artifacts/`, the vault directory, and the Chrome profile). **Delete those directories to remove the data.** The Software does not retain copies elsewhere.
- Data sent to a third‑party model provider is retained according to **that provider's** policy; use their controls to manage or delete it.

## Browser permissions (extension)

The Chrome extension requests the `debugger` permission to drive the page under test over the Chrome DevTools Protocol. Chrome displays a banner while a debug session is attached. The extension communicates only with the **local daemon on your machine** and with the model provider you configured.

## Children

The Software is a developer tool and is **not directed to children** under 16. We do not knowingly collect personal information from children.
