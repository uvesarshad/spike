## Execution protocol (for the agent working this list)

Work the list **top to bottom** (severity order). For every task:

1. Read the cited audit finding first — it carries the file:line evidence and the failure scenario; this list carries the *decision* (defaults are pre-made so you never stall on a choice).
2. After each code change: `npm run typecheck` && `npm test` must both pass. Add a fast-bucket regression test whenever a task says **Test:**. Never run `npm run test:browser`, `test:e2e`, or anything needing live Chrome, API keys, or real websites; never run `spike daemon --install-service`.
3. **Never touch the real home directory or real agent configs.** Everything that reads/writes `~/.claude`, `~/.cursor`, `~/.codex`, `~/.codeium`, `~/.gemini`, `~/.spike`, or spawns `claude`/`codex`/`osascript`/`notify-send` goes through an injectable home dir + runner (same pattern as `__setRunner` in `src/service/install-service.ts`) and is tested against a temp dir with the runner stubbed. Never run `spike setup` or `spike schedule add` for real.
4. Commit after each completed task (`fix(A<n>): <summary>` / `feat(A<n>): …` / `feat(E<n>): …`, on the current branch). **Never push.** Leave the pre-existing uncommitted change in `extension/lite-engine.js` alone — don't stage it.
5. Tick the checkbox `- [x]` and bump the `Updated:` header count as each task lands.
6. Tasks marked **⛔ OWNER** cannot be done autonomously. Skip them, leave unchecked, list them in your final summary. Tasks marked **(default: …)** contain a pre-made decision — execute it; only deviate if the code makes it impossible, and say so in the commit message. Defaults marked *(decision N)* come from the audit's "Decisions that are yours" and use its recommendation — the owner may still change the number/behaviour later.
7. Every user-facing string (CLI output, dashboard copy, skill text shown to humans) follows the vocabulary rules in [26-09-12-audit-usability-autonomy](./26-09-12-audit-usability-autonomy.md) §1.5. Skill/instruction text read by *agents* may name commands and flags.
8. Every new command or MCP tool: add it to README's commands table and to CLAUDE.md's Commands/Architecture sections in the same commit.
9. If a task is already satisfied or infeasible as written, don't silently skip: tick only if genuinely satisfied, otherwise leave unchecked with a one-line `<!-- note: ... -->` under it.
