## Execution protocol (for the autonomous agent working this list)

Work the list **top to bottom** (severity order). For every task:

1. Read the cited audit finding first — it carries the file:line evidence and failure scenario; this list carries the *decision* (defaults are pre-made so you never stall on a choice).
2. After each code change: `npm run typecheck` && `npm test` must both pass (the fast bucket is pure/in-memory — after T-A31 lands it needs no Chrome). Add a fast-bucket regression test whenever a task says **Test:**. Never run `npm run test:browser`, `test:e2e`, or anything needing live Chrome, API keys, or real websites; never run `spike daemon --install-service`.
3. Commit after each completed task (`fix(A<n>): <summary>` / `feat(E<n>): <summary>`, on the current branch). **Never push** — pushing is the owner's step.
4. Tick the checkbox `- [x]` and bump the `Updated:` header count as each task lands.
5. Tasks marked **⛔ OWNER** cannot be done autonomously (real-world submission, pushes, business decisions). Skip them, leave unchecked, and list them in your final summary. Tasks marked **(default: …)** contain a pre-made decision — execute the default; only deviate if the code makes the default impossible, and say so in the commit message.
6. If a task turns out to be already-fixed or infeasible as written, don't silently skip: tick it only if genuinely satisfied, otherwise leave unchecked with a one-line `<!-- note: ... -->` under it.
