# Folder Structure

> Scope: Every top-level directory mapped to its purpose; naming conventions and framework rules.
> Rendering context: N/A
> Project tier: 3
> Last updated: 2026-07-18

## Overview

The project is a Node.js ESM package. Source lives in src/ and compiles to dist/. Runtime artifacts (reports, screenshots) land in artifacts/. Recorded test scripts emit to generated-tests/. The Chrome extension lives under extension/ and is mostly plain MV3 JavaScript that the daemon dev-loads or the user installs — hand-written, never compiled — except extension/lite-engine.js, a checked-in build artifact bundled from src/extension/lite-engine.ts.

## Top-Level Directories

src/ — TypeScript source for the daemon, engine, CLI, and MCP server. All production code. Never imports from spikes/. Sub-packages described below.

dist/ — Build output from tsup. Two entry points: dist/cli.js (CLI binary with shebang) and dist/mcp-server.js (MCP stdio server). Sourcemaps alongside. Git-ignored; regenerated by npm run build.

extension/ — Unpacked Chrome MV3 extension. Hand-written files (sw.js, panel.html/js/css, overlay.js, nano-offscreen.html/js, manifest.json, icons/) are plain JavaScript, never compiled. One exception: extension/lite-engine.js is a generated, checked-in build artifact — `npm run build` (via `tsup --config tsup.lite.config.ts`) bundles src/extension/lite-engine.ts (browser target, Buffer-polyfilled, single ESM file) into it; sw.js `import`s it directly. Edit src/extension/lite-engine.ts, never extension/lite-engine.js by hand. Packed to dist/extension.zip by npm run pack:extension.

fixture/ — The dogfood shop app. A single Express server (fixture/server.ts) with a login → products → cart → checkout flow. Intentionally buggy when started with --bug on: "Place order" throws (order.total undefined) and /api/order returns 500. Used as the e2e oracle.

spikes/ — Frozen de-risking proof-of-concept code. Never imported by src/. Two sub-spikes: cdp-logpoint (Spike B: CDP logpoint injection) and spike-a-web.js (Spike A: Nano visual verdicts). spikes/.chrome-profile/ holds a dedicated headless/headed Chrome profile for the spikes, avoiding collision with the daemon profile.

test/ — Test suites. Named m1–m6 (contract tests) and e2e.* (end-to-end), plus numbered v1–v33 integration spikes (reference, not imported; latest additions cover telemetry spans, video assertions, action-cache-driver, and the script runner). port-contract.ts holds shared BrowserPort interface assertions.

artifacts/ — Generated run output: one subdirectory per runId containing report.json, screenshots/step-NN.png, audit.jsonl, and optionally replay.gif. Git-ignored.

generated-tests/ — Recorded test scripts emitted by the recorder after a passing run. Each script is a pair: <slug>.json (the JSON trace, role+name locators) and <slug>.spec.ts (Playwright twin). Git-ignored by default.

scripts/ — Build-time TypeScript utilities. gen-icons.ts generates extension icon assets; pack-extension.ts bundles extension/ into dist/extension.zip.

docs/ — All documentation. Subdirectories: architecture/, modules/, api/, state/, infra/ (generated docs); top-level product and research docs (human-authored).

.claude/ — Claude Code workspace: settings.local.json, run transcripts, memory/. Git-ignored.

## src/ Sub-Packages

src/ports/ — Browser and Nano port interfaces and implementations. browser-port.ts is the abstract interface; cdp-browser.ts is the CDP implementation; extension-browser.ts is the vibe-mode stub; nano-port.ts, nano-runner-page.ts, extension-nano.ts handle Gemini Nano access in both transport modes; runner-assets.ts holds the runner page HTML/JS as string literals.

src/router/ — Model ladder. adapter.ts defines the ModelAdapter interface; model-router.ts walks the ladder and builds the model_trace; gateway.ts normalizes OpenAI-compatible gateway endpoints; verdict.ts defines the NanoVerdict schema. adapters/ holds one file per rung: nano.ts, google-cli.ts, cli-planner.ts, byok-gemini.ts, anthropic.ts, openai-compatible.ts, ollama.ts.

src/telemetry/ — Process-wide span tracer, always instrumented but zero-config no-op by default. index.ts re-exports the package; tracer.ts defines TelemetrySpan/TelemetryTracer and createTelemetryTracer(); redaction.ts strips API keys, bearer tokens, cookies, passwords, secret placeholders, known secret values, and query/userinfo off URLs before a span leaves the process; otlp-exporter.ts is the only way a span ever leaves the machine (OTLP/HTTP JSON, opt-in via SPIKE_TELEMETRY_EXPORTER=otlp — serves local Tempo/Alloy, Grafana Cloud, or Axiom); env.ts builds and memoizes the default tracer from env vars (getDefaultTracer(), resetDefaultTracer()).

src/assertions/ — Assertion policy helpers. visual-policy.ts defines standalone visual verdict policies (`single-ladder`, `fail-on-disagreement`, `arbiter-on-disagreement`); policy.ts adapts those policies to ModelRouter and writes assertion_trace records for driver assertions.

src/driver/ — The a11y-tree-first test loop. loop.ts is the main orchestrator (runDriverLoop); planner-prompt.ts builds the Brain (buildGoalPlannerPrompt) and Navigator (buildNavigatorPrompt) prompts; actions.ts defines the Action union type and JSON schema. src/driver/script-runner/ is the secure custom-step escape hatch for the `script` action: schema.ts defines the small allowlisted declarative step list over BrowserPort verbs (`.strict()` zod shapes, no eval); validator.ts structurally validates steps and scans for code-injection markers before anything executes; executor.ts runs an already-validated step list against BrowserPort only, resolving `{{run.*}}`/`{{secret:NAME}}` at execute time; index.ts re-exports all three.

src/cache/ — Verified action-cache helpers. action-cache.ts builds normalized URL/goal/action/page-signature keys, stores redacted file-backed action values, rehydrates cached targets, and verifies action effects for runDriverLoop action reuse.

src/capture/ — Page introspection utilities. axtree.ts extracts and prunes the accessibility tree; console-network.ts drains and formats console errors and network failures; logpoints.ts injects CDP logpoints.

src/report/ — Output contract. report.ts defines the Report interface, StepRecord, FailingStep, and slimReport(); artifacts.ts manages the artifacts/<runId>/ directory, saves screenshots and report.json, and appends to audit.jsonl.

src/recorder/ — Run recording and replay. script.ts defines QaScript, serializes a passing run to generated-tests/, and emits the Playwright .spec.ts twin; replay.ts re-runs a script over CDP at $0; matcher.ts is the pre-run replay matcher (matchReplayScript) — before a fresh AI run, scores existing generated-tests/*.json scripts against the new task+url and, above threshold, qaRun() replays deterministically at $0 instead of spending Navigator/Brain tokens (read-only over script.ts's listScripts/loadScript; `spike run --no-replay` skips it).

src/run-data/ — In-memory non-secret runtime data. state.ts defines RunDataState/RunDataExtraction and createRunDataState(), generating {{run.email}}, {{run.shortid}}, {{run.name}}, {{run.phone}} and storing extracted values (source: dom/model/email/manual) for later same-run references; resolver.ts resolves {{run.*}} placeholders (RUN_PLACEHOLDER_RE) immediately before type actions; index.ts re-exports both.

src/email/ — Email provider contracts and local test doubles. provider.ts defines the EmailProvider interface, EmailMessage/EmailQuery, messageMatches(), and findOtp(); fake-local.ts is FakeLocalEmailProvider, an in-memory provider for OTP/signup tests; real external providers are deferred; index.ts re-exports both.

src/bridge/ — Extension↔daemon WebSocket transport. bridge-server.ts is the WS server (JSON-RPC both directions: `{id}` daemon→ext, `{rid}` ext→daemon, `{event}` fan-out); cdp-shim.ts (buildCdpClient/createCdpShim) makes any transport — the bridge, or chrome.debugger directly in Lite mode — look like a chrome-remote-interface CDP.Client, so src/capture/* and the executor run unchanged over either.

src/extension/ — TypeScript source for the daemon-less LITE engine, bundled into extension/lite-engine.js by `tsup --config tsup.lite.config.ts` (browser target; distinct from the top-level extension/ folder, which is the unpacked plain-JS MV3 extension itself). lite-engine.ts is the entry (runLite()) — composes only portable pieces (driver loop, model router, BYOK + Nano adapters, LiteExtensionBrowser, BrowserArtifactStore) and must never import engine.ts/config.ts/settings.ts/vault.ts/the CLI/Ollama (enforced by a grep gate on the emitted bundle, keeping the Node graph out of the browser bundle). lite-extension-browser.ts is LiteExtensionBrowser, the BrowserPort driving the page via chrome.debugger directly (no daemon, no WebSocket bridge) — a transport-pure clone of src/ports/extension-browser.ts. lite-nano.ts is LiteNano, the Prompt-API path for Lite mode. browser-artifacts.ts is BrowserArtifactStore, an in-memory (no filesystem in a service worker) drop-in for src/report/artifacts.ts — screenshots as base64, session-only. buffer-shim.ts is the esbuild inject target that rewires bare `Buffer` references to the feross/buffer polyfill for the SW bundle.

src/service/ — Cross-platform background-service installer. install-service.ts implements `spike daemon --install-service`/`--uninstall-service`: Windows Scheduled Task (`schtasks`, ONLOGON trigger, `/RU <user>`), macOS LaunchAgent plist (`~/Library/LaunchAgents`, RunAtLoad), Linux systemd `--user` unit. All spawns route through an internal `run()` indirection (`__setRunner` stubs it in tests — no OS persistence in test runs).

src/chrome/ — Chrome process lifecycle. launch.ts spawns or attaches Chrome; extensions.ts dev-loads the unpacked extension via CDP Extensions.loadUnpacked.

src/vibe/ — Vibe mode. service.ts is the VibeService that powers `spike daemon`; fix-prompt.ts generates paste-ready fix prompts; auto-fix.ts runs the auto-fix loop; settings-data.ts holds pure settings DATA and helpers (ProviderId, PlannerMode, ModelRole, DEFAULT_SETTINGS, PROVIDER_ORDER — no Node imports, so it's safe to bundle into src/extension/lite-engine.ts as well as the daemon); settings.ts is the daemon's fs-backed SettingsStore, re-exporting settings-data.ts and adding on-disk persistence + stale-pin migration.

src/vault/ — Credential storage. vault.ts reads/writes API keys; dpapi-key-provider.ts encrypts them with Windows DPAPI.

src/clip/ — Screencast recording. screencast.ts starts/stops a GIF clip recorder using CDP Page.startScreencast; gifenc.d.ts provides TypeScript types.

src/config.ts — Central config. Merges DEFAULTS → spike.config.json → SettingsStore → env vars → explicit overrides. Exports loadConfig() and QaConfig.

src/engine.ts — The single core orchestrator. Exports qaRun() and qaReplay(); both transports (CLI, MCP) call these. Also exports openBrowserSession() for no-model tests.

src/cli.ts — CLI entrypoint. Uses commander to register subcommands: run, replay, fixture, nano, daemon, fix, mcp, secret, config, dashboard (hand-rolled, dependency-free localhost HTML view over artifacts/<runId>/report.json — model_trace, token accounting, cache/replay stats; port 9420 default, SPIKE_DASHBOARD_PORT; defined inline in cli.ts, no separate module).

src/mcp-server.ts — MCP stdio server. Registers the qa_run tool and delegates to qaRun().

## Naming Conventions

TypeScript source files: kebab-case (e.g., cdp-browser.ts, model-router.ts).
Interfaces and types: PascalCase (e.g., BrowserPort, ModelAdapter, QaConfig).
Test files: prefix m1–m6 for contract tests, e2e.* for end-to-end, v* for numbered integration spikes.
Generated artifact directories: named by runId (a UUID-like string, e.g., artifacts/r-1234abcd/).
Script files in generated-tests/: kebab-case slug derived from the task name.

AGENT NOTE: The spikes/ directory is frozen reference code. Never import from spikes/ in src/. Never run npm install or npm run spike from the project root — those commands belong inside spikes/cdp-logpoint/ with its own package.json.

AGENT AVOID: Do not add src/ports/ implementations that bypass BrowserPort. All browser control must flow through the interface so the engine remains transport-agnostic.

## Update Triggers

- When any top-level folder is added, renamed, or removed.
- When a new src/ sub-package is created.
- When naming conventions change.
- When the build output structure changes (new entry points, new dist/ files).
