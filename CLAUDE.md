# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The **browser QA/debug subagent** product: a local daemon + (eventually) Chrome extension that lets a cheap-model ladder — Gemini Nano on-device, Gemini CLI free quota, BYOK, Ollama — do browser testing so the expensive coding agent only pays ~2K tokens per verdict. The full product vision, research, competitive landscape, and **spike results** live in `docs/spike-agent-product-doc.md` — read it first; §6.5 records what each spike proved and the gotchas hit on this machine. Demand-validation research is in `docs/grok-findings-about-auto-testing-tool.md`. A non-expert architecture walkthrough is in `docs/architecture-explainer.md`.

**The driver is a two-tier navigator/brain split** (the core cost lever — see `docs/plan/2026-07-01-planner-navigator-split.md`): a cheap/free **navigator** (`plan-step`, default Gemini Nano, $0) does the per-step page-driving on *every* step, and a smart **brain** (`plan-goals`, default Claude Sonnet) plans a sub-goal checklist *once* up front and is re-consulted only when the navigator is stuck (blocked / loops / invalid output / per-goal overflow / ambiguous final verdict). So brain cost is ~O(escalations + 1), not O(steps) — a run can go for hours over complex apps at near-navigator cost. Proven live on a live production marketing site (domain withheld) (2026-07-03): 14 Nano navigator steps vs 3 Sonnet brain calls, brain flat as steps grew; verdict payload 124 tok. Two Settings cards ("Navigator" + "Brain") expose the two roles. A single-model setup (no `plan-goals` adapter) degrades gracefully to navigator-only.

Both de-risking spikes **PASSED** (frozen reference code under `spikes/`, never imported by `src/`):
- **Spike A** — Gemini Nano (Chrome Prompt API) returns a schema-enforced JSON verdict on a page screenshot, discriminates good vs broken UI, $0 on-device (~5.5s warm).
- **Spike B** — CDP logpoints (`Debugger.setBreakpointByUrl` with a `console.log(...), false` condition) inject instrumentation into a running page with zero source edits; `Page.addScriptToEvaluateOnNewDocument` shims fetch/onerror on any site.

## Architecture (MVP)

One engine, two transports (MCP stdio + CLI), interface-driven so the extension can replace CDP later without touching the engine:

- `src/ports/` — `BrowserPort` (navigate/click/type/screenshot/axTree/logpoints/console+network drains): `CdpBrowser` is the real implementation (spawns/attaches Chrome via `--remote-debugging-port`); `ExtensionBrowser` is a deliberate stub mapping each op to its MV3 equivalent for the vibe-mode milestone. `NanoPort`: Gemini Nano via a localhost **runner page** (Prompt API is web-exposed on secure contexts; about:blank is not) — `runner-assets.ts` holds the in-page JS as string literals.
- `src/router/` — model ladder with three `Capability` roles: `visual-verdict` (Nano first, then vision cloud), `plan-step` (the **navigator** — cheap per-step action-picker; Nano serves this too via `navStep`), `plan-goals` (the **brain** — smart planner; every `plan-step` adapter also serves it EXCEPT Nano, which never plans goals). `ModelRouter` takes two pins — `navigatorAdapter` (leads `plan-step`) and `plannerAdapter` (leads `plan-goals`) — plus a `pinnedAdapter` back-compat alias applied to both; `planJson()` is the navigator call, `planGoals()` the brain call, `hasCapability(cap)` gates the navigator-only fallback. Rung 0 Nano ($0 on-device), rung 1 generic Google CLI adapter (binary from config — `gemini` today, `antigravity` after June 18 2026; never hardcode) + `CliPlannerAdapter` (`claude`/`codex`), rung 2 BYOK HTTP adapters (Gemini, Anthropic, OpenAI/OpenRouter, and **GLM/z.ai** `glm-5.2` — text-only, planner-only, `GLM_API_KEY`/`GLM_BASE_URL`), rung 3 Ollama stub. Escalates on uncertainty/unavailability; every call lands in `report.model_trace` tagged by `capability` (per-role cost split). New OpenAI-compatible providers reuse `OpenAiCompatibleAdapter` (`supportsVision`/`jsonMode`/`extraBody` knobs) — don't write a new adapter class.
- `src/driver/` — hierarchical a11y-tree-first loop (`loop.ts`): brain `planGoals` → ordered sub-goal checklist (ONE call); then per `currentGoal` the **navigator** loop — serialize tree (~800 tok) → `planJson` (navigator) picks 1–3 actions or emits `goalComplete`/`blocked` → execute via port → drain console/network per step. Stuck (`blocked`, same-action-3×, invalid JSON, per-goal overflow) → `escalate()` re-consults the brain (revised goals / hint / verdict), capped by `MAX_BRAIN_ESCALATIONS`. Vision (Nano) only on `assert_visual` + final confirm; a navigator finish that the visual disagrees with escalates to the brain for the call. `maxSteps` 40 (per-goal budget 12) → `uncertain`. No `plan-goals` adapter configured → navigator-only fallback (single implicit goal = the task). Prompts in `planner-prompt.ts` (`buildGoalPlannerPrompt` brain, `buildNavigatorPrompt` navigator); schemas in `actions.ts` (`GOAL_PLAN_JSON_SCHEMA`, `PLAN_JSON_SCHEMA` + `goalComplete`/`blocked`).
- `src/orchestrator/budget.ts` + `fan-out.ts` (A8/A11) — batch spend + shared login. `SpendBudget` sums each run's `spendSummary.estimatedUsd`; `runFanOut({budgetUsd})` skips the remaining flows (`uncertain`, "stopped: spending limit reached ($X of $Y)") once reached and hands each run the money left as `ctx.spendCapUsd` (callers merge it with `runOptionsFromContext(ctx)`); unpriced (subscription-CLI) calls are counted, not capped. `runFanOut({loginOnce})` (`batchLoginOnce(artifactsDir, saveTo?)`) asks the first passing flow whose task matches `/log ?in|sign ?in/` to save its session and starts every later flow with it (file 0600, deleted at batch end unless `--save-storage-state`). Suites/replay use `guardRuns` + `withSpendCap` for the same thing. Unattended defaults: config `unattendedBudgetUsd` ($1 per scheduled job/watch per rolling 24 h — `spentInWindow` in `src/schedule/store.ts`, real spend read back by `childRunner` via `spendSince`) and `ciBudgetUsd` ($2/`spike ci`); explicit `--budget` wins. `--stop-on-fail` / `--steps-per-flow` map to `stopOnFirstFailure` / `maxStepsPerFlow`.
- `src/driver/spec-decompose.ts` (A7) — the document front door. ONE `plan-goals` call (`buildSpecDecomposePrompt` + `SPEC_FLOWS_JSON_SCHEMA`) turns a spec/PRD/story list into `flows: [{name, task}]` (cap 20, each task ≤300 chars), then `runFlows` runs each flow as its OWN `qaRun` (sequential, sharing `--storage-state`) and `aggregateVerdict` rolls the per-flow verdicts into one (fail > uncertain > pass) which drives the exit code / tool result. Both the planning call and the per-flow runner are INJECTED (`planFlows`, `runFlow`) so the module imports neither the router nor the engine — `engine.ts`'s `createPlanningRouter()` builds the browser-free ladder for the real call sites (`spike run --spec`, `qa_run`'s `spec`/`flows` inputs). The fan-out half lives in `src/orchestrator/fan-out.ts`.
- `src/mcp-server.ts` (A4/A5) — `createMcpServer(deps)` builds EXACTLY five tools (`qa_run` [+`storageState`/`allowHosts`], `site_check`, `tests_run`, `runs_list`, `run_get`; every description ≤ 60 words — each schema costs the calling agent context every session, and `test/v112` enforces both). `site_check` runs `src/discovery/run-check.ts` (`runSiteCheck`, also holds `buildSiteMap` + the HTTP fetchers), `tests_run` runs `src/suite/run-tests.ts` (`runTests`, `labelSuiteItems`), `runs_list`/`run_get` read `src/report/run-store.ts` (`SAFE_RUN_ID`, `listRuns`, `loadRunReport` — shared with the dashboard; validate any run id from outside with `isSafeRunId`). The `qa_run` task example uses `{{secret:NAME}}` placeholders — never put a `user / password` example in a tool description. `slimReport()` adds `fix_hint` (≤1,200 chars, `buildFixHint` in `vibe/fix-prompt.js`) on `fail` only.
- `src/change-scope/change-scope.ts` (E7) — git diff → affected pages. `changedFiles(git, base?)` unions `git diff base...HEAD`, uncommitted and untracked files through an injected `GitRunner` (`realGit()` only in the CLI); `scopeFromFiles` classifies conservatively: Next `app/`/`pages/` page files → route patterns (`/products/:id`; colocated app files → `/dir/**`), docs/tests/CI-only → `skip`, ANYTHING else (shared components, styles, package.json, api routes, root layout) → `all`. `routeMatches`/`anyRouteMatches` test a path against patterns. Consumers: `spike ci --changed-since <ref>` (`CiOptions.changedSince`; skip → pass with a note, routes → `SiteCheckOptions.onlyPaths` narrows the check, falls back to all pages when none match; the saved suite still runs whole) and `spike watch --changed` (skips docs-only changes). Test `v162`.
- `src/login/login.ts` (E6) — `spike login <url> [--out]`: `runLogin(url, file, {browser, waitForDone, save})` opens a HEADED browser, waits for the human (Enter in the terminal), captures `StorageState` via `captureStorageState`, refuses an empty session, saves 0600 via `saveStorageStateFile` (default `~/.spike/sessions/<host>.json`, `defaultSessionPath(url, homeDir)`), and always closes the window. The browser is the injected `LoginBrowser` port; `createRealLoginBrowser()` (CdpBrowser, headed) is only built by the CLI — tests (`v161`) stub it, never launch Chrome.
- `src/schedule/notify.ts` (E5) — `webhookPayload(url, change)` picks the body by address: `hooks.slack.com` → `{text, attachments:[{color,text}]}`, `discord.com/api/webhooks/…` → `{content, embeds:[…]}`, anything else → the raw `StatusChange` object (unchanged). `postWebhook` never throws; used by `notifyIfFlipped` (schedule/watch, on flips) and `spike ci --webhook` (`ciStatusChange`, every run). Test `v160`.
- `src/ci/` (A9) — `spike ci --url <preview> [--suite] [--check] [--budget] [--summary] [--junit] [--comment] [--wait-for-url] [--webhook] [--changed-since]`: `ci.ts` (`runCi`, `waitForUrl` polls for a 200, default 180 s; `renderCiSummary`/`renderCiJunit`/`writeCiOutputs` also append to `$GITHUB_STEP_SUMMARY`) composes the shared `runTests` (suite) and `runSiteCheck` (check) — no new run logic; budget defaults to $2 in the CLI and is split evenly when both run; exit 0/1/2 by verdict, 3 = could not run (URL never up, nothing selected). `pr-comment.ts` builds the single PR comment body (marker `<!-- spike-ci -->`, capped) and `upsertCommentPlan` picks create-vs-update; the root `action.yml` composite Action performs it with `gh api`. Test `v131`. Runs, deps and clock are injected.

## Operational gotchas

- **Naming (post-rename):** npm package `spike-agent`, CLI binary `spike`, extension "Spike — QA testing agent", daemon "Spike Core" (OS service ids `com.spike-agent.daemon` / Windows task `Spike Core` / `spike-core.service`). Env prefix is `SPIKE_*`; `src/config.ts` reads `spike.config.json`. Four deprecation shims cover the old names and ALL go at 1.0 (`test/v34.rename-migrations.ts` guards them — delete it in the same sweep): (1) `src/env-compat.ts` aliases any lingering `QA_*` var onto `SPIKE_*` (new name wins; one-time stderr notice, silence with `SPIKE_SUPPRESS_LEGACY_ENV_WARNING=1`); (2) `CONFIG_FILENAMES` falls back to `qa.config.json`; (3) `migrateLegacyPath()` moves `qa-subagent/` → `spike/` (SettingsStore) and `qa-subagent-vault/` → `spike-vault/` (encrypted API keys) once, on first read; (4) `migrateLegacyStorage()` in `extension/sw.js` moves `chrome.storage` `qaKeys`/`qaSettings` → `spikeKeys`/`spikeSettings`. Every one of them is "new name wins, never clobber" — they carry REAL user data (API keys), so a regression orphans secrets silently rather than failing loudly. The MCP *tool* name stays `qa_run` — semantic for the calling LLM, not a brand surface.
- During Nano model download, **don't navigate the runner tab** — navigation kills the `create()` promise (component download survives; rerunning re-attaches).
- Verdict latency: ~16.7s cold (model load) vs ~5.5s warm — `NanoPort.warmup()` holds one session; never `destroy()` it between verdicts.

- **The Tier-4 guard trusts the named target automatically for CLI/MCP (`trustTargetHost`, default true in `qaRun`/`engine.ts`):** `spike run "<task>" --url <anything>` / the `qa_run` MCP tool can click/type end-to-end on ANY site/app/SaaS/no-code build (WordPress, Framer, Webflow, whatever — the driver is accessibility-tree + screenshot driven, not framework-specific) with zero flags — the URL's host, plus its www./bare-domain sibling (apex↔www redirects, e.g. a bare domain ↔ its www. subdomain, are auto-covered both directions), is added to `allowedHosts` for that run. Hosts OTHER than the named target (ad iframes, OAuth redirects to a different domain, surprise 3rd-party redirects) still default-deny mutation — add those via `--allow-host` / `SPIKE_ALLOWED_HOSTS`. The **vibe panel is the one caller that opts OUT** of this default (`trustTargetHost: false` unless its "allow click/type on this site" checkbox is on) since it drives whatever tab happens to be open, not a URL the user explicitly typed as a target — see `vibe/service.ts`. Only test sites you're authorized to drive, and scope tasks to non-destructive checks on anything you don't own outright.
- **Look-only mode (`readOnly`) follows the same named-target rule (A1, P0):** `readOnly` defaults to TRUE in config, but `qaRun` resolves the EFFECTIVE value through `resolveReadOnly()` (`src/engine.ts`): an explicit per-run `readOnly` wins; otherwise a trusted named target (`trustTargetHost`, i.e. every `spike run --url` / `qa_run` call) forces it FALSE unless some config source set it explicitly (`readOnlyWasConfigured()` in `src/config.ts` — per-run override, `SPIKE_READ_ONLY`, `spike.config.json`; deliberately NOT the SettingsStore, whose `readOnly` the old panel Save wrote unconditionally, so counting it would leave the CLI silently look-only on any machine that ever opened the panel's settings). Without that relaxation a plain `spike run` silently skipped every click and ended `uncertain` with a page of green "skipped" ticks. `spike run --read-only` / `qa_run { readOnly: true }` turn look-only mode on; `spike replay --read-only` REFUSES a saved test that clicks or types (explicit flag only — replay never reads the config value, so an on-disk `readOnly:true` can't break saved tests). A skipped mutation is recorded as a FAILED step (`ok:false`, `error: 'skipped: look-only mode'`), never a success, and both prompts are told look-only is on. In the panel there is exactly ONE control: the per-site "Allow the agent to click & type on this site" checkbox sends `readOnly: !consent` per run (the old Settings → Debugging toggle is gone; the setting key survives for env/config parity only).
